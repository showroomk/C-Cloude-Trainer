    まず必須でやること

    最初に押さえるのは2つです。研修では「反映の流れ（Save → Publish）」を体で覚えること。本番では「自分専用の管理者アカウントと MFA」を整えてから触ること。

    研修このサイトで最初にやること

    上から順に。所要時間の目安は合計30分です。

    • 1
      研修を開始する開始画面で名前を入力（何を入れても可）。開始画面 →
    • 2
      画面の見方を確認する右上の「?」でいつでも表示できます。ボタンにマウスを乗せると説明が出ます。
    • 3
      反映の流れを1回通す（最重要）Internet Firewall にルールを1つ追加し、Apply → Save → Publish。Internet Firewall →
    • 4
      Topology で全体を見る赤い拠点を開いて、切断時の画面を確認。Topology →
    • 5
      研修ミッションを残りすべて右下の「研修ミッション」から。

    本番実機の管理画面で最初に必ずやること

    設定を変える前に、これだけは済ませておきます。

    • 1
      自分専用の管理者アカウントでログインし、MFA を設定共有アカウントは使わない（Audit Trail で誰の操作か追えなくなる）。
    • 2
      自分の権限（Role）と契約範囲を確認Editor / Viewer のどちらか。マネージド契約では、自社で変更してよい範囲を販売代理店と確認。
    • 3
      正常時の状態を記録する（ベースライン）Topology の拠点数・接続状態、主要拠点の遅延・帯域を控えておくと、異常に気づけます。
    • 4
      変更のルールを決める変更申請（目的・影響範囲・切り戻し）、Publish 前のダブルチェック、ルール名の命名規則。
    • 5
      Audit Trail の確認を習慣にする障害時は「直前に誰が何を変えたか」から確認。
    絶対にやってはいけないこと：WAN Firewall の「Firewall Enabled」をオフにする（アクセス制御がなくなる）／ TLS Inspection を証明書の配布前に全社で有効化する／ 他の管理者のロックを本人に確認せず Override する。
    01

    画面の見方

    管理画面は「上部タブ → 左メニュー → 作業エリア」の3段で目的の画面にたどり着きます。メニュー名は英語なので、場所は「Monitoring > トポロジー」のように書きます。

    番号場所役割
    ①上部タブMonitoring（監視）／ Network（拠点・経路）／ Access（ユーザー）／ Security（FW・TLS）／ Administration（管理者）
    ②左メニュータブの中の画面。青い線が付いているのが今いる画面
    ③パンくず今どこにいるか。「Accounts」で開始画面に戻る
    ④操作ボタンNew（追加）／ Save（保存）／ Publish（反映）。マウスを乗せると説明が出る
    ⑤一覧行をクリックすると右側に編集パネルが開く
    ⑥操作要領 ／ ?この手順書／画面の見方の再表示
    02

    変更を反映する ― Apply → Save → Publish

    ポリシー画面（Firewall・Network Rules・TLS Inspection・Client Connectivity）の変更は、3段階を踏んで初めて全社に反映されます。画面上部の帯の色で、今どの段階かが分かります。

    1. ［New］または行のクリックで右側のパネルを開き、入力して ［Apply］。一覧に反映されるが、帯は黄色（未保存）。
    2. ［Save］で自分専用の未公開リビジョンに保存。帯は青（未公開）。他の管理者からは見えず、触ったルールはロックされる。
    3. ［Compare View］で変更点を確認してから ［Publish］ → 確認画面でもう一度 ［Publish］。帯が緑になり、全社に反映。
    Publish は取り消せません。戻したいときは「逆の変更」をもう一度 Save → Publish します。やめたいときは Publish 前に［Discard］。
    Internet Firewall で練習する →
    03

    ルールは上から順に評価される

    通信は一番上のルールから順に照合され、最初に一致したルールで結果が決まります。どれにも一致しなければ、一番下の既定ルールが適用されます。既定ルールの中身は画面によって逆なので注意します。

    「許可ルールを追加したのに見られない」ときは、そのルールより上にある Block ルールに先に当たっていないか確認します。Position（Rule Order）で上に移動します。
    04

    拠点（サイト）を追加する

    Network > サイト > New

    先に管理画面でサイトを作っておけば、現地では Sokket に回線と LAN をつないで電源を入れるだけで接続されます（ゼロタッチ）。

    番号項目入力のポイント
    ①Site Name命名規則を決める（例：JP-TKY-HQ ＝ 国-都市-拠点）
    ②Connection TypeSokket の型番・vSokket・IPsec。作成後は変えられないので正確に
    ③Country / City / Time Zone最寄り PoP と、Sokket 自動アップグレードの時間帯に影響
    ④WAN 帯域ライセンス帯域に合わせる。2本目の回線は Enable WAN2
    ⑤Native Range拠点LANのサブネット（例 10.30.0.0/24）。他拠点と重複させない
    ⑥License地域・帯域に合ったライセンスを選び［Apply］
    Sites で練習する →

    拠点の状態を見る

    Monitoring > トポロジーNetwork > サイト > {拠点} > スナップショット / Network Analytics

    毎朝、Topology で赤い拠点がないかを確認します。気になる拠点はクリックして Snapshot（今の状態）と Network Analytics（24時間の推移）を見ます。

    Topology で練習する →
    06

    固定IPで外に出す ― IP Allocation と NAT

    Network > アイピー・アロケーションNetwork > ネットワーク・ルール

    Kato を通すと、送信元IPは PoP の共有IPに変わります。IPアドレスで接続制限している取引先・SaaS には、自社専用の Allocated IP から出すように設定します。

    1. Network > アイピー・アロケーション で Location（例：Tokyo）を選び［Allocate］→［Save］。割り当てられたIPを控える。
    2. Network > ネットワーク・ルール で［New］→ New Rule。Rule Type は Internet、App/Category で対象サービスを指定。
    3. Configuration の Route/NAT で NAT を選び、Allocated IP を指定 → Apply → Save → Publish。
    4. 取引先・SaaS の管理者に、その IP を許可リストへ登録してもらう。
    IP Allocation で練習する →
    07

    Web会議を優先する ― Bandwidth Priority

    Network > ネットワーク・ルールNetwork > バンドウィドス・マネジメント

    回線が混んだとき、どの通信を先に流すかを決めます。数字が小さいほど優先。ルールを作っただけでは既定の p255（最後）になります。

    Network Rules で練習する →
    08

    TLS Inspection（HTTPS の検査）

    Security > ティーエルエス・インスペクション

    暗号化された通信を PoP で一度開けて検査し、もう一度暗号化して送ります。端末にルート証明書が入っていないと証明書エラーになります。

    1. MDM（Intune など）でルート証明書を全端末に配布する（有効化より先に）。
    2. パイロットユーザーに限定して「Enable TLS Inspection」をオン → Save → Publish。
    3. 動かなくなったアプリを Events で探し、Bypass ルールを追加 → Save → Publish。
    4. 問題が出なくなってから対象を全社に広げる。
    TLS Inspection で練習する →
    09

    ユーザーとリモート接続

    Access > ユーザーAccess > ディレクトリ・サービスAccess > クライアント・コネクティビティ・ポリシー

    ユーザーは IdP（Entra ID など）から SCIM で自動同期するのが基本です。リモート接続できるかは、SDP ライセンスの有無と Client Connectivity Policy で決まります。

    退職者対応は IdP 側でアカウントを無効化するのが原則です。SCIM で同期されたユーザーを Kato 側だけで消しても、次の同期で戻ります。
    Client Connectivity Policy で練習する →
    10

    Events で原因を探す

    Monitoring > イベント

    「このサイトが見られない」と言われたら、Events でどのルールに止められたかを確認します。

    イベントが表示されるまで約5分、まれに30分かかります。ルールの Track（記録）がオフだと、そのルールのイベントは残りません。
    Events で練習する →

    拠点がつながらないときの切り分け

    上から順に確認します。各段で原因が見つかれば、その右の対応を行います。
